# 代码标准分析器

## 概述

此技能分析代码是否符合行业标准和最佳实践，帮助开发人员维护高质量的代码库。

## 分析内容

### 1. 代码风格
- **缩进**：一致使用空格或制表符
- **命名规范**：变量、函数、类遵循语言特定的命名约定
- **行长度**：符合推荐的行长度限制
- **空白字符**：运算符和括号周围的适当间距
- **注释**：充分且有意义的文档

### 2. 最佳实践
- **错误处理**：适当的异常处理和错误管理
- **性能**：潜在的性能瓶颈
- **安全性**：常见的安全漏洞
- **内存管理**：适当的资源分配和释放
- **代码重复**：检测冗余代码

### 3. 潜在问题
- **未使用的变量**：声明但未使用的变量
- **不可达代码**：永远无法执行的代码
- **死代码**：从未被调用的函数或代码块
- **逻辑错误**：代码中潜在的逻辑问题
- **依赖问题**：过时或易受攻击的依赖项

## 支持的语言

- Python
- JavaScript/TypeScript
- Java
- C/C++
- Go
- Ruby
- PHP

## 使用方法

### 基本分析
分析单个文件：

```
分析代码标准 for <文件路径>
```

### 目录分析
分析整个目录：

```
分析代码标准 in <目录路径>
```

### 特定语言分析
使用特定语言的标准分析代码：

```
分析 <语言> 代码标准 for <文件路径>
```

## 分析输出

分析将提供：

1. **摘要报告**：整体合规分数和关键发现
2. **详细问题**：发现的具体问题及行号
3. **建议**：提高代码质量的建议
4. **最佳实践**：发现的良好实践

## 示例

**输入：**
```
分析代码标准 for src/utils.py
```

**输出：**
```
# 代码标准分析报告

## 摘要
- 总体分数：85/100
- 发现问题：5
- 最佳实践：12

## 详细问题
1. 第42行：变量 'temp' 已声明但未使用
2. 第67行：行长度超过80个字符
3. 第89行：函数 'calculate_metrics' 缺少文档字符串
4. 第123行：缩进不一致（混合使用空格和制表符）
5. 第156行：嵌套循环存在潜在性能问题

## 建议
- 删除未使用的变量 'temp'
- 将长行拆分为多行
- 为 'calculate_metrics' 函数添加文档字符串
- 标准化缩进到4个空格
- 考虑重构嵌套循环以提高性能

## 观察到的最佳实践
- 使用 try-except 块进行适当的错误处理
- 函数命名约定一致
- 良好使用模块化代码结构
- 为复杂逻辑提供充分的注释
```

## 集成

此技能可以集成到：
- 预提交钩子
- CI/CD 管道
- 代码审查工作流程
- 开发 IDE

## 配置

分析器默认使用行业标准规则，但可以根据提供的项目特定指南进行自定义。

## 限制

- 无法检测所有逻辑错误
- 在某些边缘情况下可能产生误报
- 需要清晰的代码结构才能进行准确分析
- 对于非常大的代码库，性能可能会有所不同
